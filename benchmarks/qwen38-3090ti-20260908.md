# Qwen3.8-27B Q3 / RTX 3090 Ti draft sweep

Local measurements, September 8, 2026. Raw timings, token counts and output
hashes are in [the JSON dataset](qwen38-3090ti-20260908.json).

## Setup

- RTX 3090 Ti, 450 W power limit; sampled clocks 1950 MHz core / 10501 MHz
  memory, no hardware/software thermal slowdown flags at the sampled point.
- xllamacpp 2026.9.10809; Unsloth UD-Q3_K_XL target, pinned Inco Q4_K_M draft.
- 220,000 allocated context, q4_0 target KV, full GPU offload, one slot,
  batch 1024 / ubatch 512, Flash Attention enabled, no n-gram stacking.
- MTP control uses the worker's existing n-max 2 / p-min 0.1 configuration.
  DFlash uses p-min 0.0 and the indicated n-max.
- First-use warmup excluded. Each measured output was 256 tokens. Code and
  prose requests use the same frozen code prefix; cache reuse is enabled and
  recorded separately from actual prompt length.
- Prefix is `Pipes.py` from commit `e180f83`, SHA-256
  `85cda58aaf9bfca6289c8b9830207d5f6174ca160633b5c08faf7105b61c3690`.
- Greedy: two repetitions per request type and context. Thinking: one per
  request type/context, with ezlocalai's real thinking profile (temperature 1,
  top-p 0.95, top-k 20, xhigh effort). These are small workload samples, not
  statistically established optima.

## Interpretation

- Three is the selected 3090-family starting profile for this fleet's long
  Q3 workload: ~34% faster than seven and ~6% faster than MTP in the sampled
  long thinking requests. It is not the winner for every request type.
- Short thinking still favors MTP; DFlash four beats three there. Preserve
  `LLM_SPECULATIVE_TYPE=mtp` and explicit draft-length overrides for A/B tests.
- The new 4090/5090 four-token profiles are **unmeasured starting points**,
  not extrapolated performance claims. No remote worker was upgraded here.
- At the 5090's reported 262,144 context, this model's target KV grows from
  about 4.5 GiB (Q4) to 8.5 GiB (Q8). Its reported ~7.88 GiB free would leave
  ~3.9 GiB at otherwise unchanged settings. Q8 is a precision upgrade, not a
  demonstrated speed improvement. Keep Q4 on the 24 GB cards at long context.
- Wider greedy outputs were not bit-identical to no speculation for either
  MTP or DFlash. The earlier two short completion smoke prompts had matched
  for DFlash, but that did not generalize. The measurements do not establish
  why outputs differ or quantify any quality impact; target verification and
  unchanged sampling settings are not a substitute for a quality evaluation.
- The benchmark deliberately does not change weight quantization or production
  sampling to chase speed. These results do not support a >100 t/s promise on
  this card, or predictions of a 5090 percentage gain.

## Reproduce on an idle worker

Use the frozen source prefix above as `--prompt-file` and stop the resident
server before loading another copy of the target on the same GPU.

```bash
python benchmark_speculative.py --context 220000 --tokens 256 \
  --draft-lengths 3,4,5,7 --prompt-chars 0,120000,360000 \
  --prompt-file /path/to/frozen-Pipes.py --repeats 2 --kv-cache q4_0

python benchmark_speculative.py --context 220000 --tokens 256 \
  --backends mtp,dflash2 --draft-lengths 7,4,3 --prompt-chars 0,360000 \
  --prompt-file /path/to/frozen-Pipes.py --repeats 1 \
  --sampling-profile thinking --kv-cache q4_0
```

The harness clears deployment-specific per-card overrides so explicit benchmark
axes actually take effect. For the 5090, repeat the same test with `--kv-cache
q8_0` and a context representative of its workload; monitor headroom throughout.
